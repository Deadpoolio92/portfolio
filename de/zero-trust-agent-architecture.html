01 // Bedrohungslage & Angriffsvektoren

Das Dilemma autonomer Enterprise-Agenten: Warum nett bitten scheitert

Autonomen LLMs ohne Leitplanken rohen Terminal-Zugriff und API-Keys zu geben, ist ein Rezept fürs Desaster. Der Branchenstandard der „Modell-Selbstkontrolle“—also „Bitte lösche keine Dateien“ in den System-Prompt zu schreiben—ist ein Witz. Versteckte Prompt-Injections auf Webseiten, Tracking-URLs in Open-Source-Tools und Modell-Halluzinationen umgehen Prompt-Regeln mühelos. Echte Sicherheit braucht deterministische Out-of-Band-Firewalls, die gefährliche Befehle stoppen, bevor sie das Betriebssystem erreichen.

Bedrohungsvektor 01

Remote Code Execution & Festplatten-Löschung

Halluzinierende oder gekaperte Modelle führen destruktive Shell-Befehle wie rm -rf /, del /s /q, git push --force oder ungesicherte Datenbank-Drops aus. Ein einziger falscher Befehl vernichtet ungesicherte Arbeit oder zerschießt Remote-Repositories.

Bedrohungsvektor 02

Credential- & Secret-Exfiltration

Agenten, die Projektordner durchsuchen, saugen .env-Dateien, id_rsa-SSH-Keys und Cloud-Tokens ein und leaken private Zugangsdaten in externe LLM-Inferenz-Logs oder ausgehende HTTP-Endpunkte.

Bedrohungsvektor 03

Indirekte Prompt-Injection

Bösartige Anweisungen in abgerufenen Webseiten, HTML-Kommentaren oder Dependency-READMEs kapern die Denkschleife des Agenten und bringen das Modell dazu, unerlaubte Aktionen mit Entwicklerrechten auszuführen.

Bedrohungsvektor 04

Supply-Chain-Poisoning & MCP-Tool-Drift

Externe Model-Context-Protocol-(MCP-)Server und GitHub-Repos schieben stille Upstream-Updates nach und schleusen unautorisierte Hintergrund-Daemons, Krypto-Miner oder Telemetrie-Beacons in zuvor vertrauenswürdige Tools ein.

01

Deterministisches AST- & Mojibake-Ingestion-Gate

Ausführungs-Direktive: Scannt Kandidaten-Pakete auf Harness-spezifische Token-Leaks und doppelt kodierte cp1252-Mojibake-Artefakte. Stoppt die Ingestion-Pipeline bei Fehlern sofort mit Exit Code 1.

scripts/audit-arsenal.ps1 (Harness-Neutrality & Mojibake Gate) 
# Extract from scripts/audit-arsenal.ps1 (Universal Harness-Neutrality Gate & Mojibake Check)
$Script:CcTokens = @('Read','Edit','NotebookEdit','Write','Glob','Grep','Bash','Agent','Task','WebSearch','WebFetch','AskUser')
$Script:AgTokens = @('read_file','edit_file','write_file','run_command','execute_script','search_web','ask_question','fetch_web_page')

# 1. Harness Neutrality Linter: Artifacts must never leak vendor-specific tokens
function Test-HarnessNeutrality {
    param([string]$FilePath, [string]$Content)
    foreach ($token in ($Script:CcTokens + $Script:AgTokens)) {
        if ($Content -match "\b$token\b" -and $FilePath -notmatch "(_arsenal\.yml|references/)") {
            Write-Error "VIOLATION: Vendor token '$token' leaked into canonical artifact: $FilePath"
            return $false
        }
    }
    return $true
}

03 // Runtime-Ausführungs-Firewall

PreToolUse-Lifecycle-Interception: Gefährliche Befehle Out-of-Band stoppen

Die wichtigste Schicht der Zero-Trust-Architektur greift zur Laufzeit. Wann immer ein Agent einen Shell-Befehl ausführen, eine Datei lesen oder einen Subagenten starten will, feuert der Harness einen PreToolUse-Hook. Dieser läuft Out-of-Band direkt in der OS-Shell. Liefert der Hook Exit Code 2 oder ein Deny zurück, wird die Ausführung sofort abgebrochen, bevor die Shell das Dateisystem überhaupt berührt.

Runtime-Hook 01 // Cross-Harness-Interception

Multi-Dialekt-Decision-Adapter (Universelles Harness-Protokoll)

Gibt strukturierte Entscheidungs-Payloads aus, die gleichzeitig zu Google Antigravity, Claude Code und DeepSeek Harness kompatibel sind.

01

Multi-Dialekt-Output-Adapter

Ausführungs-Direktive: Formatiert Intercept-Entscheidungen parallel in alle drei großen Hersteller-Schemas. So steuert ein einziges PowerShell-Skript Claude Code, Antigravity und DeepSeek Harness ohne Code-Duplizierung.

library/hooks/secrets-guard/secrets-guard.ps1 (Write-Decision Function) 
# Multi-Dialect Hook Output Adapter Function (Production Code: library/hooks/secrets-guard/secrets-guard.ps1)
function Write-Decision {
    param([string]$Decision, [string]$Reason)
    $hookEventName = if ($payload.hook_event_name) { $payload.hook_event_name } else { "PreToolUse" }
    @{
        # Dialect 1: Google Antigravity Format
        decision = $Decision
        reason = $Reason
        # Dialect 2: Claude Code Standard Format
        permissionDecision = $Decision
        permissionDecisionReason = $Reason
        # Dialect 3: DeepSeek Harness & Claude Code Nested Spec
        hookSpecificOutput = @{
            hookEventName = $hookEventName
            permissionDecision = $Decision
            permissionDecisionReason = $Reason
        }
    } | ConvertTo-Json -Compress
}
Runtime-Hook 02 // Destructive-Execution-Firewall

Das Execution-Gate (Dual-OS-Regex-Denylist)

Prüft Shell-Kommandos vor der Ausführung. Blockt destruktive Dateisystem-Befehle, ungesicherte Datenbank-Drops und erzwungene Git-Branch-Überschreibungen hart ab.

02

Dual-OS-Interceptor für destruktive Befehle

Ausführungs-Direktive: Gleicht vorgeschlagene Shell-Strings gegen eine harte plattformübergreifende Regex-Denylist ab. Sendet ein hartes Deny und bricht bei Treffern mit Exit Code 2 ab.

library/hooks/security-gate/security-gate.ps1 (Dual-OS Regex Denylist) 
# Production Code: library/hooks/security-gate/security-gate.ps1 (Dual-OS Denylist)
$patterns = @(
    # Unix & Cross-Platform Destructive Patterns
    'rm -rf', 'rm -fr', 'sudo rm', 'chmod -R 777', 'mkfs', 'dd if=', ':\(\)\{:\|:&\};:',
    
    # Windows PowerShell Destructive Patterns
    'Remove-Item\s+(-Recurse|-Force)', 'ri\s+.*(-r|-fo)', 'rd\s+/s\s+/q', 'del\s+/s\s+/q',
    'Clear-Disk', 'Format-Volume',
    
    # Git Destructive History & Branch Overwrites
    'git push .*(\+|--force|-f\b|--force-with-lease)',
    'git reset --hard', 'git clean -fd', 'git clean -f', 'git branch -D',
    'git checkout \.', 'git restore \.',
    
    # Database Unconstrained Deletion Patterns
    'DROP TABLE', 'DROP DATABASE', 'TRUNCATE TABLE', 'DELETE FROM .* WHERE 1=1'
)

foreach ($pat in $patterns) {
    if ($cmd -match "(?i)$pat") {
        $msg = "BLOCKED by security-gate: destructive pattern detected ($pat)."
        [Console]::Error.WriteLine($msg)
        [Console]::Error.WriteLine("   If this is intentional, run it manually in your terminal.")

        Write-Decision -Decision "deny" -Reason "$msg Command: $cmd"

        if (-not $isAntigravity) { exit 2 }
        exit 0
    }
}

04 // Subagenten-Grenzmatrix

Prinzip der minimalen Rechte: Autonome Subagenten eingrenzen

In einem Multi-Agent-System ist es ein architektonisches Anti-Pattern, jedem Agenten das komplette Toolkit zu geben. Ein Codebase-Researcher hat auf der Festplatte oder in der Shell nichts zu suchen. Ein Umsetzungs-Subagent gehört auf seinen zugewiesenen Branch und darf weder Code pushen noch deployen. Wir erzwingen eine strikte Role-Based-Access-Control-(RBAC-)Matrix, die exakt festlegt, welche Tools jeder Agent anfassen darf.

Subagenten-Rolle Erlaubte Tool-Domäne Hart entzogene / verbotene Tools Workspace-Grenze & Isolationsstandard
researcher Read-Only write_file, edit_file, run_command, Bash Triage-Sandbox in research/; bewertet externe Kandidaten-Repos ohne Schreibrechte auf die produktive library/.
librarian Vault-Ops WebSearch, WebFetch, externe Netzwerk-Endpunkte Strikte lokale Vault-Operationen (library/, index.md, log.md); physisch von ausgehenden HTTP-Calls getrennt.
code-builder Task-Scoped Write git push, git commit, git merge, Deploy-Skripte Auf deklarierte Task-Dateien in einem isolierten Git-Branch begrenzt; darf nicht stagen, committen oder zum Remote pushen.
code-reviewer Read-Only QA write_file, edit_file, sed, In-Place-Dateimutationen Kalter Second-Opinion-Reviewer; prüft Git-Diffs und liefert strukturierte Findings ohne Befugnis, Quellcode anzufassen.
security-gate Runtime-Hook Selbstmutation, Umgehung des Exit-Code-2-Vertrags Out-of-Band-OS-Ausführungs-Interceptor; prüft Shell-String-Syntax, bevor überhaupt ein Prozess gestartet wird.
05 // Supply-Chain-Provenance & Upstream-Radar

Radar v2: Automatisierte Upstream-Drift-Erkennung & 3-Wege-Merge-Reviews

Open-Source-KI-Tools entwickeln sich rasend schnell. Wenn ein Upstream-Autor ein Repository ändert, auf das du dich verlässt, holst du dir mit blindem Pulling schnell Backdoors und Prompt-Injections in die Produktion. Karol baute Radar v2—eine automatisierte Drift-Monitoring-Engine, die 25+ Upstream-GitHub-Repos überwacht, strukturierte AST-Delta-Briefs erzeugt und ein explizites menschliches Sicherheits-Urteil verlangt, bevor Code überhaupt gestaged werden darf.

Stufe 01: Drift-Scan

Watch-Universe-Delta-Erkennung

Ein nächtlicher Cron-Job führt radar.ps1 scan über alle überwachten Upstream-Repos aus und vergleicht kryptografische SHA-256-Hashes gegen gespeicherte Baselines.

Stufe 02: Delta-Brief

Librarian-AST-Inspektion

Erzeugt menschenlesbare Delta-Briefs, die Upstream-Änderungen in neue Fähigkeiten, Verhaltensänderungen oder potenzielle Angriffsflächen kategorisieren.

Stufe 03: Human-Gate

Striktes Prüf-Urteil

Der Operator prüft den Brief und vergibt ein dauerhaft protokolliertes Urteil: clean, skip, absorb oder ticket.

Stufe 04: Atomarer Swap

Staging & Rollback-Verifikation

Übernahmen stagen Updates in isolierten temporären Verzeichnissen. Komplette Linter-Suites laufen durch, bevor die Produktions-Bibliothek atomar aktualisiert wird.

Die Sicherheits-Retrospektive: 3 Regeln, die wir hart gelernt haben

Regel 01

Lass ein Modell niemals sich selbst überwachen

System-Prompts sind unverbindliche Bitten; Betriebssystem-Hooks sind Pflicht. Vertraue niemals darauf, dass ein LLM „Sicherheitsregeln“ befolgt, wenn eine Zeile Out-of-Band-PowerShell-Regex Compliance deterministisch erzwingen kann.

Regel 02

Tools auf das absolute Minimum kürzen

Wenn ein Agent Code recherchieren oder Doku lesen soll, gib ihm keine Bash-Tools. Wenn ein Agent Dateien editieren soll, gib ihm keine Rechte zum Pushen in die Produktion. Least Privilege verhindert 99 % aller Unfälle.

Regel 03

Vertraue keinem Upstream ohne Diff

Open-Source-KI-Pakete ändern sich über Nacht. Blindes git pull auf fremden Agenten-Repos ist eine offene Einladung für Supply-Chain-Angriffe. Prüfe immer zuerst die AST-Delta-Briefs, bevor Code übernommen wird.
