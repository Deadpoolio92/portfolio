01 // Architecture & Decomposition

Ditching the "God Prompt": Why Monolithic Prompts Break Down

Most enterprise AI workflows try to build a single "God Prompt". They paste a 50-page operating manual, 20 API tool schemas, and thousands of lines of code into one massive prompt, and pray the AI doesn't break things. In real life, that fails hard: the model gets confused and forgets rules, costs explode to $34+ a session, and asking it nicely not to delete files is wishful thinking. Here is how my Conductor-Subagent mesh fixes it.

The Monolithic "God Prompt" Trap

Single Massive Context (80k–120k Tokens Re-Sent Every Turn)

One Generalist Agent • 300 KB Instructions Loaded on Startup

How Most People Do It: Force one generalist AI to juggle product specs, coding standards, database schemas, and terminal execution all at once. Every follow-up query retransmits 80,000+ tokens of dead weight, driving costs to $34+ per session and triggering severe hallucination loops.

  • Attention Loss: The AI forgets rules in the middle of long prompts and starts hallucinating.
  • Burning Cash: 50 turns burn 6.85M tokens, costing $34.25+ with painful 24-second waits.
  • Fake Safety: Begging an agent "please don't break production" fails when errors happen.
Karol's Production Standard

Autonomous Conductor + Ephemeral Single-Job Subagents

1 Task = 1 Clean Window • Physically Stripped Tools • Real OS Hooks

How Karol Builds It: An autonomous Conductor breaks work into bite-sized tasks, spawns single-purpose subagents with physically stripped tool manifests, and requires consecutive clean review passes before anything gets merged.

  • Fresh Contexts: Subagents spawn with 0 prior turns, touch only briefed files, and vanish when done.
  • 76.8% Token Cut: Memory stays flat at ~4.2k tokens, dropping session costs to $7.95 and latency to 4.8s.
  • Unbreakable OS Gates: Out-of-band PowerShell hooks kill bad commands before a shell ever spawns.

02 // Least Privilege & Sandboxing

Physical Tool Stripping: Why Telling Agents "Don't Edit Files" Fails

Beginner agent setups give every model full system access (Read, Write, Bash, Git, Network) and then try to tell it in plain English: "Please only review code, do not edit files." That is a complete joke. When an agent hallucinates or encounters an edge case, it will edit files anyway. In my setup, we use physical tool stripping: if an auditor agent does not need to edit files, the write_file tool is physically deleted from its manifest. Even if an adversarial prompt tries to hijack it, the tool literally does not exist.

## Cold Review Mandate & Zero Rationalization
You are a staff-level code reviewer doing a pre-delivery review. You have no knowledge
of what the implementing session intended or rationalized. You review the code as it is,
cold. Never soften findings because the code "seems to work" or "is probably fine."

## Specialist Dispatch (On by Default — Parallel Subagent Swarm)
Beyond your own 7 Review Dimensions, decide which bundled specialist checklists in
<AGENT_DIR>/resources/specialists/ are relevant and dispatch EACH as a parallel subagent:
- security.md        — auth/session/token/role changes or backend diff > 100 lines
- performance.md     — algorithmic complexity, hot-path allocations, unindexed filters
- red-team.md        — adversarial attack vectors, silent failures, trust boundary exploits
- error-handling.md  — exception swallowing, unhandled promise rejections, recovery chains
- api-contract.md    — API/OpenAPI/GraphQL breaking changes and backward compatibility
- data-migration.md  — schema/migration changes, zero-downtime rollbacks

Dispatch relevant specialists in a SINGLE message so they execute in parallel.
Each specialist subagent returns strict JSON: {"severity":"CRITICAL|INFORMATIONAL","confidence":N,"path":"...","line":N,...}
Merge specialist findings into your own 3-tier output; dedupe across all sources.

## Systemic Pattern Sweep (Mandatory on Defect Discovery)
The moment you flag a regex or algorithmic defect (e.g. an O(n²) pattern or bad complexity),
immediately grep the REST of the codebase for the same pattern before finishing the round.
A fix in one file never implies the pattern was swept everywhere else it appears.

## Follow-Up Round Comparison Engine
When a prior report is supplied, track state transitions explicitly:
- ✅ CONFIRMED FIXED — what was wrong, confirmed resolved with evidence
- 🟡 PARTIALLY FIXED  — what changed, what's still incomplete or wrong
- 🆕 NEW INDEPENDENT — issue surfaced by this round's broadened scope
- ⚠️ NEW REGRESSION  — defect directly introduced by a prior round's fix

## Authority & First Step: Direct Questimus REST Ingestion
The brief's task block does not carry the task's full text: it carries the Questimus sub-issue
identifier. Your FIRST STEP before any other work: read that exact sub-issue via the
questimus skill:
  node <path-to-questimus.js> get <id>
What you read directly from Questimus is authoritative and complete.

## Absolute Branch & Git Lockdown
Work on the branch the brief states — never create, switch, or delete branches.
YOU NEVER git add, NEVER git commit, NEVER push.
The conductor reviews the working tree, stages, and commits. Leave every change unstaged.

## Scope Lock & Environment Freeze
Build ONLY the task's declared Files. If you find the task genuinely cannot be done
within that list, STOP and report that fact — do not expand scope to make it work.
Fixes stay minimal and inside the Files list; unrelated bugs are reported, never fixed.
The conductor's environment state is binding: if impossible, STOP and report.

## Mandatory Red-Before-Green TDD
When the task prescribes TDD: write the failing test first and show it RED before implementing.
The red run's output MUST be pasted in your Evidence — a red-before-green claim without
the pasted red output is UNPROVEN and rejected.

## Non-Negotiable Output: DEBUG REPORT Block
End every single run with exactly this structured block:
  ## DEBUG REPORT — <task id>
  **What was built**: <summary>
  **Files touched**: <exact list — must match task's declared Files>
  **Evidence**:
  - <command> → <pasted real output, truncated only for length, never summarized>
  **Status**: verified | best-effort | reverted

03 // Operating System Defense

Non-Bypassable OS Hooks: Stopping Disasters Before the Shell Spawns

Natural-language guardrails (e.g. "You are a helpful assistant. Do not execute destructive commands") are wishful thinking. In complex codebases, recursive error loops, adversarial prompt injection, and hallucinations will eventually bypass text rules. Our rule is dead simple: Never trust an AI to self-police. Deterministic code must govern probabilistic models—put a real script in front of the model that slams the door shut.

PreToolUse Interception Architecture (JSON IPC Hook)

Stage 01

Tool Call Request

Autonomous agent requests shell execution (e.g., run_command("rm -rf ./build")).

Stage 02

Payload Interception

Harness intercepts execution request out-of-band and pipes JSON payload into STDIN of security-gate.ps1.

Stage 03

Deterministic Regex Audit

Hook parses command string against 19 destructive regex signatures (force-push, disk wipes, hard resets).

Stage 04

Exit Code 2 Hard Block

Destructive pattern detected: hook emits exit code 2 to stderr. The OS shell never spawns. Zero damage possible.

Active Blocked Signatures in Production (Exit Code 2 Hard Blocks)

Threat Category Target Signature (Regex Pattern) Operational Risk Mitigated Hook Action
Filesystem Wipe rm -rf, rm -fr, sudo rm Irreversible deletion of build assets or project source trees Exit Code 2
Git History Destruction git push --force, git push -f, git reset --hard Overwriting remote commit history or uncommitted working state Exit Code 2
Branch Corruption git branch -D Force-deleting branches containing unmerged production code Exit Code 2
Working Tree Wipe git checkout \., git restore \., git clean -f Silently discarding uncommitted local engineering work Exit Code 2
Database Annihilation DROP TABLE, DROP DATABASE, TRUNCATE TABLE Catastrophic drop of relational tables in local or container databases Exit Code 2
Host System Damage & Fork Bombs mkfs, dd if=, chmod -R 777, :\(\)\{:\|:&\};: Filesystem corruption, permission stripping, and fork bombs Exit Code 2

Production PreToolUse Hook Implementation (Verified Real PowerShell Script)

.agents/hooks/security-gate/security-gate.ps1 
# security-gate.ps1 — PreToolUse hook, blocks destructive Bash / run_command commands
# Hook event: PreToolUse -> bash | run_command
# Exit 2 = hard block (Claude Code/DSH); Exit 0 with decision: "deny" (Antigravity)

$ErrorActionPreference = 'Stop'
$InputJson = [Console]::In.ReadToEnd()

$cmd = ''
$isAntigravity = $false
try {
    $data = $InputJson | ConvertFrom-Json
    if ($null -ne $data.tool_input -and $null -ne $data.tool_input.command) {
        $cmd = [string]$data.tool_input.command
    } elseif ($null -ne $data.toolCall -and $null -ne $data.toolCall.args -and $null -ne $data.toolCall.args.CommandLine) {
        $cmd = [string]$data.toolCall.args.CommandLine
        $isAntigravity = $true
    }
} catch {
    $cmd = ''
}

# 19 Patterns that are hard-blocked regardless of context (case-insensitive)
$patterns = @(
    'rm -rf', 'rm -fr', 'git push --force', 'git push -f ', 'git push -f$',
    'git reset --hard', 'git clean -fd', 'git clean -f', 'git branch -D',
    'git checkout \.', 'git restore \.', 'DROP TABLE', 'DROP DATABASE',
    'TRUNCATE TABLE', 'DELETE FROM .* WHERE 1=1', 'mkfs', 'dd if=',
    'chmod -R 777', 'sudo rm', ':\(\)\{:\|:&\};:'
)

foreach ($pat in $patterns) {
    if ($cmd -match "(?i)$pat") {
        $msg = "BLOCKED by security-gate: destructive pattern detected ($pat)."
        [Console]::Error.WriteLine($msg)
        [Console]::Error.WriteLine("   Pattern: $pat")
        [Console]::Error.WriteLine("   Command: $cmd")
        [Console]::Error.WriteLine("   If this is intentional, run it manually in your terminal.")

        if (-not $isAntigravity) {
            exit 2 # Claude Code & DSH: Exit 2 halts execution immediately
        }
        @{ decision = "deny"; reason = "$msg Command: $cmd" } | ConvertTo-Json -Compress
        exit 0
    }
}

if ($isAntigravity) { @{ decision = "allow" } | ConvertTo-Json -Compress }
exit 0 # Verified clean: tool allowed

05 // State Persistence & Resumption

Stateless LLMs, Persistent Memory: Wiping Context to 0 Tokens Without Losing Progress

Large language models are stateless compute engines, not databases. If you keep 50 turns of back-and-forth chat in memory, the context window fills up with junk and the model starts drifting. In my architecture, we can wipe the agent's context completely to 0 tokens at any time without losing a single line of progress. All operational state is externalized to Questimus (our internal project management, ticketing and tracking tool) via REST API through a clean two-level continuity model.

Level 01: Macro State

The Project HANDOFF Page

Stores high-level system state, current release version, active git branch, verified test suites, and discovered landmines. Checked automatically at session start; serialized and committed via REST at session close.

node questimus.js handoff • Restores full session in <200ms
Level 02: Micro State

Atomic Ticket Description Appends

Mid-task progress, failing test output, and fix evidence are appended directly into the active ticket description (safe description-only editing; never uneditable comments). Any fresh agent can resume mid-task without reading conversation logs.

node questimus.js update <id> --desc-file .tmp/progress.md

Command-Line Interface State Protocol (Questimus REST Wrapper)

State Serialization Commands (PowerShell) 
# 1. Read macro session context at startup (restores state in <200ms)
node .agents/skills/questimus-arsenal/scripts/questimus.js handoff

# 2. Append in-flight atomic progress to active ticket description
node .agents/skills/questimus-arsenal/scripts/questimus.js update TASK-104 --desc-file .tmp/progress.md

# 3. Serialize end-of-session run state to persistent database
node .agents/skills/questimus-arsenal/scripts/questimus.js handoff --write-file .tmp/handoff-state.md
