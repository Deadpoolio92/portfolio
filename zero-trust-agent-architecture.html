1.0 Threat Landscape, Enterprise Vulnerabilities & Defense Blueprint

Security Blueprint • Out-of-Band Interception

Empirical threat breakdown: Moving from probabilistic model self-policing to deterministic, out-of-band execution gates.

§ 1.1 Executive Threat Analysis: The Enterprise Autonomous Agent Dilemma

Enterprise adoption of autonomous coding agents and workflow orchestrators has reached an inflection point. While autonomous systems yield massive productivity gains, default tool installations expose internal infrastructure to severe security risks. When probabilistic models control shell execution or filesystem access without deterministic gates, traditional application security fails.

1. Arbitrary Shell Execution (Remote Code Execution)

Hallucinated or poisoned model decisions execute destructive shell commands (rm -rf, git push --force, DROP TABLE), wiping uncommitted work or corrupting remote repositories.

2. Credential & Secret Exfiltration

Autonomous agents reading project directories inadvertently ingest sensitive files (.env, .ssh/id_rsa, cloud provider tokens) and leak them into external LLM provider logs or prompt context.

3. Indirect Prompt Injection & Context Poisoning

Malicious payloads embedded in untrusted web pages, dependency readmes, or Git commit logs hijack model reasoning loops, triggering unauthorized secondary actions under the agent's elevated permissions.

4. Supply-Chain Poisoning & MCP Tool Drift

Third-party Model Context Protocol (MCP) servers and external skills receive silent upstream updates, injecting unauthorized background network daemons, telemetry beacons, or compromised tool definitions.

§ 3.1 Multi-Dialect PreToolUse Intercept Architecture

Because Karol operates autonomous agents across four distinct runtime harnesses (Google Antigravity, Claude Code, DeepSeek Harness, and Gemini CLI), hooks must not depend on vendor-specific intercept formats. His hooks implement a universal adapter pattern emitting decisions to all three major JSON schemas simultaneously:

Multi-Dialect Hook Output Adapter Function (library/hooks/secrets-guard/secrets-guard.ps1)
# Multi-Dialect Hook Output Adapter Function (Production Code: library/hooks/secrets-guard/secrets-guard.ps1) function Write-Decision { param([string]$Decision, [string]$Reason) $hookEventName = if ($payload.hook_event_name) { $payload.hook_event_name } else { "PreToolUse" } @{ # Dialect 1: Google Antigravity Format decision = $Decision reason = $Reason # Dialect 2: Claude Code Standard Format permissionDecision = $Decision permissionDecisionReason = $Reason # Dialect 3: DeepSeek Harness Codec Format hookSpecificOutput = @{ hookEventName = $hookEventName permissionDecision = $Decision permissionDecisionReason = $Reason } } | ConvertTo-Json -Compress -Depth 5 }

The security-gate.ps1 hook intercepts proposed commands in the PreToolUse event. To guarantee security in Windows PowerShell and cross-platform container environments, it evaluates commands against a dual-OS audited denylist before shell invocation:

• sudo rm / chmod 777

• git push .*(\+|--force)

§ 3.3 The Credential Boundary (secrets-guard.ps1): Tiered Secret Isolation

To prevent credential leaks into model contexts or web logs, secrets-guard.ps1 intercepts file access tools (Read, Edit, view_file) and enforces a strict three-tier authorization policy:

Production Code: library/hooks/secrets-guard/secrets-guard.ps1
# Production Code: library/hooks/secrets-guard/secrets-guard.ps1 $envExclusions = @(".env.example", ".env.sample", ".env.template") if (-not ($envExclusions -contains $basenameFull)) { # Tier 1 Hard Deny: Environment files with active secrets if ($basenameFull -imatch "^\.env(\..+)?$") { Write-Decision -Decision "deny" -Reason "Blocked by secrets-guard: credential file pattern (.env)." return } # Tier 1 Hard Deny: SSH directory and private keys if ($norm -imatch "(^|/)\.ssh/" -or $basenameNoExt -imatch "^(id_rsa|id_ed25519|id_ecdsa)$") { Write-Decision -Decision "deny" -Reason "Blocked by secrets-guard: SSH private key store." return } # Tier 1 Hard Deny: Cloud credentials, session tokens, and cryptographic certificates if ($norm -imatch "(^|/)\.aws/" -or $basenameFull -ieq ".claude.json" -or $ext -imatch "^\.(pem|key|pfx)$") { Write-Decision -Decision "deny" -Reason "Blocked by secrets-guard: token store / certificate." return } } # Tier 2 Confirmation: Heuristic keyword inspection for non-standard files if ($basenameFull -imatch "credentials" -or $basenameFull -imatch "secrets") { Write-Decision -Decision "ask" -Reason "secrets-guard: filename matches heuristic credential pattern. Confirm before proceeding." return }

§ 3.4 Least-Privilege Tool Filter (smart-permission-filter.ps1)

Balances security with developer velocity. Safe, idempotent read operations (Read, Glob, Grep, LS, read_file, list_dir, search_files, view_file) are silently auto-approved, while file mutations are written to an immutable local audit log (.agents/hook-log.txt):

Production Code: library/hooks/smart-permission-filter/smart-permission-filter.ps1
# Production Code: library/hooks/smart-permission-filter/smart-permission-filter.ps1 $readonlyTools = @('Read', 'Glob', 'Grep', 'LS', 'read_file', 'list_dir', 'search_files', 'view_file', 'search_web', 'TodoRead', 'TaskGet', 'TaskList') $writeTools = @('Write', 'Edit', 'MultiEdit', 'NotebookEdit', 'write_to_file', 'replace_file_content') if ($readonlyTools -contains $tool) { Write-Allow # Auto-approve safe read operations with zero latency } if ($writeTools -contains $tool) { # Record mutation telemetry with UTC timestamp, target tool, and caller context $timestamp = (Get-Date).ToUniversalTime().ToString('yyyy-MM-ddTHH:mm:ssZ') Add-Content -Path '.agents/hook-log.txt' -Value "$timestamp WRITE $tool" Write-Allow }

4.0 Subagent Boundary Isolation & Least-Privilege Execution Matrix

Role-Based Access Control • Ephemeral Sandboxing

Role-Based Access Control (RBAC): Architectural tool strip-down, ephemeral git worktrees & isolated throwaway databases.

§ 4.1 Principle of Least Privilege in Multi-Agent Systems

In standard agent deployments, a single model session holds all available tools (bash execution, file writes, web fetching, and database connections). Under adversarial injection or model drift, compromising any aspect of the session yields full system control.

Karol solves this by decomposing work across specialized subagents with physically restricted toolsets. A research agent analyzing untrusted public documentation is physically incapable of running shell commands or modifying files, neutralizing remote code execution (RCE) vectors by design.

§ 4.3 Workspace Boundary Isolation: Worktrees, Ephemeral Schemas & Ports

Ephemeral Git Worktrees

Implementation tasks execute in separate git worktrees (git worktree add). Incomplete edits or unexpected file creation cannot contaminate main branch state.

Throwaway Schemas

Database integration tests run against isolated PostgreSQL schemas provisioned dynamically per test run and dropped immediately upon completion, preventing test-state leakage.

Loopback Port Slots

Services bind exclusively to loopback addresses (127.0.0.1:7030–7039). Agents are physically blocked from publishing ports to external 0.0.0.0 interfaces.

5.0 Supply-Chain Provenance & Radar v2 Automated Drift Detection

Supply-Chain Defense • Upstream Drift Engine

Eliminating upstream poisoning: Immutable snapshot materialization, 3-way delta briefs & human-directed merge verification.

§ 5.1 The Upstream Dependency Attack Surface

External skills and Model Context Protocol (MCP) packages are living software dependencies. Open-source repositories regularly update prompts, tool definitions, or dependencies. Without cryptographic pinning and drift detection, an upstream maintainer can:

1. Silent Prompt Poisoning

Upstream authors modify system prompt instructions to alter agent behavior or inject hidden instructions.

2. Telemetry Infiltration

New updates quietly add network pings or telemetry trackers that leak local file paths or environment variables.

3. Breaking Schema Drift

Uncoordinated tool argument renames cause downstream autonomous agents to fail mid-execution during production runs.

§ 5.2 Radar v2: 5-Stage Human-Directed Drift & Absorption Protocol

Karol engineered Radar v2 to monitor the entire monitored repository watch-universe. External updates are never automatically pulled into production; they pass through an immutable snapshot staging pipeline:

1 SCAN

Fetches upstream commit tree hash & diff.

2 SNAPSHOT

Materializes exact snapshot in raw/radar/.

3 BRIEF

Generates 3-way AST & token delta brief.

4 DECIDE

Human signs off: clean | absorb | skip.

5 ABSORB

Promotes to library & bumps semver.
