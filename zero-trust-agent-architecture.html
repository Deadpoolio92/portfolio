01 // Threat Landscape & Attack Vectors

The Enterprise Autonomous Agent Dilemma: Why Asking AI Nicely Fails

Giving autonomous LLMs raw terminal access and API keys without guardrails is a recipe for disaster. The industry standard of 'model self-policing'—putting "Please don't delete files" into a system prompt—is a complete joke. Hidden prompt injections in untrusted web pages, sneaky tracking URLs in open-source tools, and model hallucinations easily bypass prompt instructions. Real security requires deterministic, out-of-band execution firewalls that kill dangerous commands before they ever reach the operating system.

Threat Vector 01

Remote Code Execution & Disk Wiping

Hallucinated or poisoned models run destructive shell commands like rm -rf /, del /s /q, git push --force, or unconstrained database drops. A single bad command wipes uncommitted engineering work or corrupts remote repositories.

Threat Vector 02

Credential & Secret Exfiltration

Agents reading project directories vacuum up .env files, id_rsa SSH keys, and cloud tokens, leaking private credentials into external third-party LLM inference logs or outbound HTTP endpoints.

Threat Vector 03

Indirect Prompt Injection

Malicious instructions hidden in fetched web pages, scraped HTML comments, or dependency READMEs hijack the agent's reasoning loop, tricking the model into executing secondary unauthorized actions under elevated developer permissions.

Threat Vector 04

Supply-Chain Poisoning & MCP Tool Drift

Third-party Model Context Protocol (MCP) servers and external GitHub repos push silent upstream updates, injecting unauthorized background daemons, crypto-miners, or telemetry beacons into previously trusted tools.

# Extract from scripts/audit-arsenal.ps1 (Universal Harness-Neutrality Gate & Mojibake Check)
$Script:CcTokens = @('Read','Edit','NotebookEdit','Write','Glob','Grep','Bash','Agent','Task','WebSearch','WebFetch','AskUser')
$Script:AgTokens = @('read_file','edit_file','write_file','run_command','execute_script','search_web','ask_question','fetch_web_page')

# 1. Harness Neutrality Linter: Artifacts must never leak vendor-specific tokens
function Test-HarnessNeutrality {
    param([string]$FilePath, [string]$Content)
    foreach ($token in ($Script:CcTokens + $Script:AgTokens)) {
        if ($Content -match "\b$token\b" -and $FilePath -notmatch "(_arsenal\.yml|references/)") {
            Write-Error "VIOLATION: Vendor token '$token' leaked into canonical artifact: $FilePath"
            return $false
        }
    }
    return $true
}

03 // Runtime Execution Firewall

PreToolUse Lifecycle Interception: Killing Dangerous Commands Out-of-Band

The most critical layer in the zero-trust architecture operates at runtime. Whenever an agent decides to run a shell command, read a file, or spawn a subagent, the harness triggers a PreToolUse hook. The hook runs out-of-band in the native operating system shell. If the hook returns exit code 2 or a deny decision, execution is immediately aborted before the shell ever touches the filesystem.

Runtime Hook 01 // Cross-Harness Interception

Multi-Dialect Decision Adapter (Universal Harness Protocol)

Emits structured decision payloads compatible with Google Antigravity, Claude Code, and DeepSeek Harness formats simultaneously.

01

Multi-Dialect Output Adapter

Execution Directive: Formats intercept decisions into all three major vendor schemas simultaneously. Enables a single PowerShell script to govern Claude Code, Antigravity, and DeepSeek Harness without code duplication.

library/hooks/secrets-guard/secrets-guard.ps1 (Write-Decision Function) 
# Multi-Dialect Hook Output Adapter Function (Production Code: library/hooks/secrets-guard/secrets-guard.ps1)
function Write-Decision {
    param([string]$Decision, [string]$Reason)
    $hookEventName = if ($payload.hook_event_name) { $payload.hook_event_name } else { "PreToolUse" }
    @{
        # Dialect 1: Google Antigravity Format
        decision = $Decision
        reason = $Reason
        # Dialect 2: Claude Code Standard Format
        permissionDecision = $Decision
        permissionDecisionReason = $Reason
        # Dialect 3: DeepSeek Harness & Claude Code Nested Spec
        hookSpecificOutput = @{
            hookEventName = $hookEventName
            permissionDecision = $Decision
            permissionDecisionReason = $Reason
        }
    } | ConvertTo-Json -Compress
}
Runtime Hook 02 // Destructive Execution Firewall

The Execution Gate (Dual-OS Regex Denylist)

Inspects shell command payloads before execution. Hard-blocks destructive filesystem operations, unconstrained database drops, and forced git branch overwrites.

02

Dual-OS Destructive Command Interceptor

Execution Directive: Matches proposed shell execution strings against a rigid cross-platform regex denylist. Emits a hard deny and exits with code 2 if any forbidden destructive pattern is detected.

library/hooks/security-gate/security-gate.ps1 (Dual-OS Regex Denylist) 
# Production Code: library/hooks/security-gate/security-gate.ps1 (Dual-OS Denylist)
$patterns = @(
    # Unix & Cross-Platform Destructive Patterns
    'rm -rf', 'rm -fr', 'sudo rm', 'chmod -R 777', 'mkfs', 'dd if=', ':\(\)\{:\|:&\};:',
    
    # Windows PowerShell Destructive Patterns
    'Remove-Item\s+(-Recurse|-Force)', 'ri\s+.*(-r|-fo)', 'rd\s+/s\s+/q', 'del\s+/s\s+/q',
    'Clear-Disk', 'Format-Volume',
    
    # Git Destructive History & Branch Overwrites
    'git push .*(\+|--force|-f\b|--force-with-lease)',
    'git reset --hard', 'git clean -fd', 'git clean -f', 'git branch -D',
    'git checkout \.', 'git restore \.',
    
    # Database Unconstrained Deletion Patterns
    'DROP TABLE', 'DROP DATABASE', 'TRUNCATE TABLE', 'DELETE FROM .* WHERE 1=1'
)

foreach ($pat in $patterns) {
    if ($cmd -match "(?i)$pat") {
        $msg = "BLOCKED by security-gate: destructive pattern detected ($pat)."
        [Console]::Error.WriteLine($msg)
        [Console]::Error.WriteLine("   If this is intentional, run it manually in your terminal.")

        Write-Decision -Decision "deny" -Reason "$msg Command: $cmd"

        if (-not $isAntigravity) { exit 2 }
        exit 0
    }
}

04 // Subagent Boundary Matrix

Principle of Least Privilege: Confining Autonomous Subagents

In a multi-agent system, giving every agent the full toolkit is an architectural anti-pattern. A codebase researcher has zero business writing to disk or running shell commands. An implementation subagent should be confined to its assigned branch and barred from pushing code or deploying. We enforce a strict Role-Based Access Control (RBAC) matrix that defines exactly what tools each agent is permitted to touch.

Subagent Role Permitted Tool Domain Hard-Stripped / Forbidden Tools Workspace Boundary & Confinement Standard
researcher Read-Only write_file, edit_file, run_command, Bash Triage sandbox in research/; evaluates external candidate repos without write privileges to production library/.
librarian Vault-Ops WebSearch, WebFetch, external network endpoints Strictly local vault operations (library/, index.md, log.md); physically blocked from outbound HTTP calls.
code-builder Task-Scoped Write git push, git commit, git merge, deploy scripts Confined to declared task files in isolated git branch; forbidden from staging, committing, or pushing to remote.

Open-source AI tools move fast. When an upstream author updates a repository you rely on, pulling changes blindly is how backdoors and prompt injections enter production. Karol built Radar v2—an automated drift-monitoring engine that tracks 25+ upstream GitHub repositories, generates structured AST delta briefs, and requires an explicit human security verdict before code can ever be staged.

Stage 01: Drift Scan

Watch-Universe Delta Detection

Nightly cron runs radar.ps1 scan across all monitored upstream repos, computing cryptographic SHA-256 hashes against stored baselines.

Stage 02: Delta Brief

Stage 03: Human Gate

Strict Adjudication Verdict

The operator reviews the brief and assigns a permanent recorded verdict: clean, skip, absorb, or ticket.

Stage 04: Atomic Swap

Staging & Rollback Verification

Absorptions stage updates in isolated temporary directories. Full linter suites run before atomically updating the production library.

The Security Retrospective: 3 Rules We Learned the Hard Way

Rule 01

Never Let a Model Police Itself

System prompts are advisory; operating system hooks are mandatory. Never trust an LLM to follow "security guidelines" when a single line of out-of-band PowerShell regex can prove compliance deterministically.

Rule 02

Strip Tools to the Absolute Minimum

If an agent is meant to research code or read documentation, don't give it bash tools. If an agent is meant to edit files, don't give it permission to push to production. Least privilege prevents 99% of accidents.

Rule 03

Never Trust Upstream Without a Diff

Open-source AI packages change overnight. Blindly running git pull on external agent repositories is an open invitation for supply-chain attacks. Always inspect AST delta briefs before promoting code.
